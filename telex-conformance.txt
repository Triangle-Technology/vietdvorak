# telex-conformance.txt — canonical conformance vectors for the VietDvorak
# Telex engine (VietDvorak.ahk :: Transform()).
#
# ROLE: this file is the SINGLE SOURCE OF TRUTH for Telex behaviour. The AHK
# input method and the practice.html trainer must both agree with it; when they
# disagree, THIS FILE IS RIGHT and the implementation is wrong. Any change to
# the engine's observable behaviour must land here in the same commit.
# `node check-parity.mjs` runs every vector below through BOTH engines.
#
# FORMAT: one case per line, `input<TAB>expected`. Lines starting with # are
# comments; blank lines are ignored. A line `@section <name>` opens a section
# and says HOW the following inputs are fed to the engine — every vector must
# sit under one, and the two sections are not interchangeable:
#
#   @section transform
#       `input` is a sequence of LETTER keystrokes typed into an EMPTY buffer.
#       Each character is fed to transform()/Transform() in turn; `expected` is
#       the buffer after the last one. No non-letter may appear here: a space,
#       a digit or a punctuation mark would end the syllable, and this section
#       has no notion of a syllable ending.
#
#   @section integration
#       `input` may contain ANY character. Each character goes through the
#       per-keystroke apply path — the layer that consults the syllable-break
#       rule and only then calls transform():
#           break char  -> commit the buffer, append the char literally, buffer := ""
#           other char  -> buffer := transform(buffer, char)
#       `expected` is committed + buffer after the last character. These vectors
#       drive the break rule END TO END — through the apply path and out into the
#       text — for the characters they type. A mismatch there does not merely
#       mistype the current syllable: it rewrites text that is already committed,
#       which is how "Vieetj-Nams" once produced "Viết-Nam".
#
#       They are NOT the only thing pinning that rule. The rule is written twice
#       — practice.html's isResetChar/LETTER_KEY, and VietDvorak.ahk's
#       VkEndsSyllable() under the banner "KẾT THÚC ÂM TIẾT" — and
#       check-parity.mjs ALSO sweeps VkEndsSyllable() across its whole VK range
#       and compares it to isResetChar() key by key, then asserts by name the
#       keep-alive codes no character can reach (Shift, VK_PACKET, Backspace) and
#       the ones that must never be kept alive (Enter, Delete, the arrows...).
#       The two halves do not overlap and neither replaces the other: the sweep
#       proves the two implementations agree on every key, including the many no
#       vector can type; the vectors below prove the agreed rule produces the
#       right TEXT once it reaches the buffer. Delete either and a hole opens.
#
#       What is still outside both: the hotkey-registration loop at the bottom of
#       that banner's block. Installing the rule means creating a real keyboard
#       hook, so nothing can execute it under test — its loop bound and hotkey
#       flags are checked as TEXT by check-parity.mjs (assertRegistration) and its
#       control flow is not checked at all.
#
# NOTE on tone placement: generated with TONE_PLACEMENT_MODERN := true, i.e.
# hoà / khoẻ / thuỷ. Flipping that constant in VietDvorak.ahk changes exactly
# the oa / oe / uy open-syllable cases below (to hòa / khỏe / thủy) and nothing
# else.
